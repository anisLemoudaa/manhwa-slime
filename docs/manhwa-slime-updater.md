# نظام تحديث MANHWA SLIME

## ما تم ربطه

يقرأ التطبيق الإصدار المنشور من:

1. `https://manhwa-slime.pages.dev/api/version?variant=standard` عند توفر Cloudflare Function.
2. جدول `app_releases` العام في Supabase كمسار احتياطي إذا كان نشر Pages يدويًا لا يشغّل مجلد `functions`.
3. GitHub Releases الحالي كمسار احتياطي أخير للحفاظ على وظيفة التحديث الموجودة.

لا يتطلب التطبيق عنوانًا جديدًا داخل الإعدادات؛ عنوان الموقع مثبت في `ReleaseServiceImpl.kt`، ومفتاح Supabase المستخدم هو المفتاح العام الموجود أصلًا في تكامل MANHWA SLIME.

## المقارنة والأمان

- المقارنة الأساسية باستخدام `versionCode` عندما يرسله الإصدار الرسمي.
- لا يُعرض تحديث عند فشل الاتصال أو عند JSON غير صالح.
- لا يُقبل رابط الإصدار الرسمي إلا عبر HTTPS.
- التنزيل والتثبيت يستفيدان من آلية التطبيق الحالية و`FileProvider` وPackage Installer، مع موافقة Android المعتادة.
- `mandatory=true` يخفي خيار التأجيل، لكنه لا يتجاوز حماية Android أو يثبت التطبيق بصمت.

## اختبار يدوي

1. أنشئ إصدارًا تجريبيًا في لوحة الإدارة برقم `versionCode` أكبر من `34` ورابط APK صالح عبر HTTPS.
2. انشر الإصدار للنسخة `standard`.
3. ثبّت نسخة التطبيق الحالية ذات `versionCode=34`.
4. افتح التطبيق أو شاشة About واضغط فحص التحديث.
5. تحقق من ظهور رقم الإصدار وملاحظات الإصدار وزر التنزيل.
6. اختبر أيضًا إصدارًا برقم أقل؛ يجب ألا يظهر كتحديث.
7. اختبر إيقاف الشبكة أو JSON غير صالح؛ يجب أن يستمر التطبيق دون تعطل ودون تحديث وهمي.

## التوقيع

يجب أن يكون APK الجديد موقّعًا بنفس مفتاح النسخ المثبتة، وأن يكون `applicationId` هو `com.manhwaslime.app`، وألا ينخفض `versionCode`. لا تضع ملف JKS أو كلمات المرور في المستودع.
